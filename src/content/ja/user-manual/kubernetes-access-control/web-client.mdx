# Web ClientでKubernetesクラスターに接続する

### Overview

KAC Web Clientを使用すると、Agentのインストールなしでブラウザから直接Kubernetesクラスターに接続し、リソースを参照・管理できます。

<Callout type="info">
KAC Web Clientは現在Beta機能です。上部GNBメニューの**Web Client**から直接アクセスするか、**Kubernetes**メニューのクラスター詳細画面で`Connect`ボタンをクリックして利用できます。
</Callout>

### Roleの選択

<figure data-layout="center" data-align="center">
<img src="/user-manual/kubernetes-access-control/web-client/connections-role-select.png" alt="QueryPie Web &gt; Kubernetes &gt; Kubernetes &gt; Select a Role" width="760" />
<figcaption>
QueryPie Web &gt; Kubernetes &gt; Kubernetes &gt; Select a Role
</figcaption>
</figure>

1. 上部GNBメニューで**Kubernetes**をクリックします。
2. **Select a Role**モーダルで使用するRoleを選択し、`Select`をクリックします。
    1. Roleによってアクセス可能なクラスターリストが異なります。
    2. 付与されたRoleがない場合、左側のリストは表示されません。WorkflowメニューのAccess Role Request様式から適切な権限を申請してください。

### クラスターへの接続

<figure data-layout="center" data-align="center">
<img src="/user-manual/kubernetes-access-control/web-client/connections-cluster-detail.png" alt="QueryPie Web &gt; Kubernetes &gt; Kubernetes &gt; Cluster Detail" width="760" />
<figcaption>
QueryPie Web &gt; Kubernetes &gt; Kubernetes &gt; Cluster Detail
</figcaption>
</figure>

1. Role選択後、左側パネルで接続したいクラスターをクリックします。
2. 右側の詳細画面で以下の情報を確認します。
    1. **Cluster Endpoint**: KubernetesクラスターのAPI URL
    2. **Expiration Date**: 現在の権限の有効期限
    3. **Status**: 権限のステータス（Active/Inactive）
    4. **Assigned Policies**: このクラスターに適用されているポリシー一覧。虫眼鏡アイコンをクリックするとポリシーの詳細を確認できます。
3. `Connect`ボタンをクリックするとWeb Client IDEに移動します。

<Callout type="info">
`Open Agent`ボタンをクリックすると、従来のAgent方式でも接続できます。Agentのインストール方法は[Agentマニュアル](../user-agent)を参照してください。
</Callout>

### Web Client画面構成

<figure data-layout="center" data-align="center">
<img src="/user-manual/kubernetes-access-control/web-client/web-client-ide-overview.png" alt="QueryPie Web &gt; Web Client &gt; Cluster Overview" width="760" />
<figcaption>
QueryPie Web &gt; Web Client &gt; Cluster Overview
</figcaption>
</figure>

接続するとクラスターの全体状況を確認できる**Cluster Overview**画面が表示されます。

* 左サイドバー（**リソースブラウザー**）: クラスター内のリソースをカテゴリ別に参照します。
* 右メインエリア: 選択したリソースの一覧または詳細情報を表示します。
* 下部パネル: PodのログビューアーとShellターミナルをタブ形式で実行します。

### リソース一覧の確認

<figure data-layout="center" data-align="center">
<img src="/user-manual/kubernetes-access-control/web-client/web-client-resource-list.png" alt="QueryPie Web &gt; Web Client &gt; Resource List" width="760" />
<figcaption>
QueryPie Web &gt; Web Client &gt; Resource List
</figcaption>
</figure>

左サイドバーでリソースの種類を選択すると、該当するリソース一覧が表示されます。

* `All Namespaces`ドロップダウンで特定のNamespaceを選択して絞り込めます。
* `Filter by name`検索ボックスに名前の一部を入力してリソースを検索できます。
* `+ Create`ボタンで新しいリソースを作成できます。

サイドバーで参照できるリソースカテゴリは以下のとおりです。

| カテゴリ | リソース種別 |
|---------|------------|
| **Cluster** | Namespace, Node, PersistentVolume, ClusterRole, ClusterRoleBinding |
| **Workloads** | Pod, Deployment, StatefulSet, DaemonSet, ReplicaSet, Job, CronJob |
| **Config & Storage** | ConfigMap, Secret, PersistentVolumeClaim, StorageClass |
| **Network** | Service, Ingress, NetworkPolicy, Endpoints |
| **RBAC** | Role, RoleBinding, ServiceAccount |
| **Custom Resources** | クラスターに定義されたCRDリソース |

### リソースの詳細確認

リソース一覧でアイテムをクリックすると、右側に詳細パネルが開きます。

#### Overviewタブ

<figure data-layout="center" data-align="center">
<img src="/user-manual/kubernetes-access-control/web-client/web-client-resource-detail-overview.png" alt="QueryPie Web &gt; Web Client &gt; Resource Detail &gt; Overview" width="760" />
<figcaption>
QueryPie Web &gt; Web Client &gt; Resource Detail &gt; Overview
</figcaption>
</figure>

リソースのメタデータとステータスを確認できます。

* **Metadata**: Name、Namespace、UID、作成日時、Status、Resource Version
* **Controlled By**: このリソースを管理する上位リソース（例: Pod → DaemonSet）。名前をクリックすると上位リソースの詳細画面に移動します。
* **Containers**: Podの場合、コンテナごとのイメージ、Readyステータス、Restartsの回数を確認できます。
* **Labels / Annotations**: リソースに設定されたラベルとアノテーション

#### YAMLタブ

<figure data-layout="center" data-align="center">
<img src="/user-manual/kubernetes-access-control/web-client/web-client-resource-detail-yaml.png" alt="QueryPie Web &gt; Web Client &gt; Resource Detail &gt; YAML" width="760" />
<figcaption>
QueryPie Web &gt; Web Client &gt; Resource Detail &gt; YAML
</figcaption>

リソースのYAML定義全体を確認・編集できます。`Edit`ボタンをクリックすると編集モードになり、保存するとクラスターに即座に反映されます。

#### Eventsタブ

<figure data-layout="center" data-align="center">
<img src="/user-manual/kubernetes-access-control/web-client/web-client-resource-detail-events.png" alt="QueryPie Web &gt; Web Client &gt; Resource Detail &gt; Events" width="760" />
<figcaption>
QueryPie Web &gt; Web Client &gt; Resource Detail &gt; Events

このリソースに関連するKubernetesイベントを確認できます。ステータス変化、スケジューリング、エラー発生時にイベントが記録されます。Podが正常に動作中の場合、イベントが表示されないことがあります。

#### Relationsタブ

<figure data-layout="center" data-align="center">
<img src="/user-manual/kubernetes-access-control/web-client/web-client-resource-detail-relations.png" alt="QueryPie Web &gt; Web Client &gt; Resource Detail &gt; Relations" width="760" />

現在のリソースに関連するリソースの階層構造をツリー形式で視覚化します。親/子関係にあるリソースを一目で把握でき、アイテムをクリックすると関連リソースの詳細画面に直接移動できます。

### PodのログをVIEWする

<figure data-layout="center" data-align="center">
<img src="/user-manual/kubernetes-access-control/web-client/web-client-log-viewer.png" alt="QueryPie Web &gt; Web Client &gt; Log Viewer" width="760" />
<figcaption>
QueryPie Web &gt; Web Client &gt; Log Viewer
</figcaption>
</figure>

1. サイドバーで**Pod**を選択し、確認したいPodをクリックします。
2. 詳細パネル右上の`Logs`ボタンをクリックします。
3. 下部パネルにそのPodのリアルタイムログがストリーミングされます。
    1. `Search logs`入力欄にキーワードを入力してログを検索できます。
    2. `Follow`チェックボックスをオンにすると最新のログに自動スクロールします。

### PodのShellターミナルへの接続

<figure data-layout="center" data-align="center">
<img src="/user-manual/kubernetes-access-control/web-client/web-client-shell-terminal.png" alt="QueryPie Web &gt; Web Client &gt; Shell Terminal" width="760" />
<figcaption>
QueryPie Web &gt; Web Client &gt; Shell Terminal
</figcaption>
</figure>

1. サイドバーで**Pod**を選択し、接続したいPodをクリックします。
2. 詳細パネル右上の`Shell`ボタンをクリックします。
3. 下部パネルにインタラクティブターミナルが開き、Podコンテナに直接コマンドを実行できます。

<Callout type="info">
LogsとShellは同時に複数タブで開いて使用できます。各タブにはPod名が表示されるため、複数PodのログとターミナルをWrap並べて比較しながら作業できます。
</Callout>

<Callout type="info">
**Q. Web Clientと従来のAgent方式の違いは何ですか？**

A. Web Clientはブラウザのみでリソースの参照、ログ確認、Shellアクセスが可能です。Agent方式は`kubectl`などのローカルツールとの連携でより幅広い操作が行えます。両方式とも同じ権限モデル（Role、Policy）のもとで動作します。
</Callout>
